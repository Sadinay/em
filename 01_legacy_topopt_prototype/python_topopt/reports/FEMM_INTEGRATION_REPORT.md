# 单进程FEMM接入与验证报告

## 环境

- FEMM 4.2：`C:\femm42\bin\femm.exe`
- Python接口：`pyfemm 0.1.3`
- COM依赖：`pywin32 312`
- 基准空白模型：`FP\CLONALG\blank_18x10.FEM`
- 几何模式：`historical_inset`
- 执行模式：单worker、单FEMM实例、独立工作目录；没有并行。

## 已实现调用链

```text
Chromosome(180)
  -> historical_precheck
  -> IsolatedFemmEvaluator
  -> 唯一case目录和模型副本
  -> 独立Python worker
  -> FEMM COM
  -> historical_inset建模命令
  -> 设置Air gap角度及六电路电流
  -> mi_analyze / mi_loadsolution
  -> mo_blockintegral(22)
  -> 标量目标函数
```

执行器会保存任务JSON、生成的FEM、结果JSON和worker标准输出/错误日志。超时发生在worker进程外部，因此可以终止阻塞的COM调用，并只清理由该任务新启动的FEMM/fkern进程。启动前默认拒绝连接到已经存在的FEMM进程，避免误用或终止用户手工打开的实例。

## 真实运行结果

### 1. 固定历史模型探针

模型：`FP\CLONALG\best_J0.150072_20251230_212929.fem`

| 项目 | 结果 |
|---|---:|
| 机械角度 | 0° |
| 转矩 | 0.7664794602301663 Nm |
| 求解时间 | 30.1965 s |
| 后处理时间 | 0.0498 s |
| 总时间 | 30.5605 s |

这证明Python→COM→FEMM求解器→转矩积分的基础链路可运行。

### 2. 180位染色体重建模型

输入：`best_result_20260306_174158.mat` 内历史最优染色体。

| 项目 | 结果 |
|---|---:|
| Python historical_inset建模 | 9.3764 s |
| 0°求解 | 183.9212 s |
| 后处理 | 0.0854 s |
| 总时间 | 193.7805 s |
| 0°转矩 | 0.8038586040546016 Nm |

### 3. 与MATLAB保存FEM模型对照

对 `FP\IA_test_Float\best_J0.0924955_20260306_174158.fem` 在相同0°、3.5 A条件下重新求解：

| 模型 | 0°转矩 |
|---|---:|
| Python由染色体重建 | 0.8038586040546016 Nm |
| MATLAB历史保存FEM | 0.8038585948719479 Nm |
| 绝对差 | 9.1826537×10⁻⁹ Nm |

单角度结果达到约1.14×10⁻⁸相对差，支持染色体排列、六扇区镜像、铜内缩、材料、电路、匝数以及FEMM调用已经整体接通。

### 4. 超时清理

将固定模型超时设为2秒后，执行器按预期终止worker并识别、清理本任务新启动的PID 8376和27116。结束后系统中没有残留FEMM或fkern进程。

## 尚未完成的验证

- 没有执行完整六角度扫描。高分辨率模型单角度约184秒，六点串行预计超过18分钟。
- 因为只计算一个角度，脉动率必为0；本次单角度J不能与历史 `0.09249546785567309` 比较。
- 还没有进行5个个体、20个体CLONALG或50个体稳定性测试。
- 当前每个个体启动一个隔离FEMM实例，稳定但启动成本较高；实例安全复用需在连续测试后实现。
- `failure_objective=1e7` 是新增的运行保障值，不是从MATLAB确认的历史参数。
- `merged_copper_v5` 仍未并入兼容模式。

## 性能判断

本次Python拓扑建模约9秒、后处理不足0.1秒，主要瓶颈是FEMM求解本身。进入批量前应先分析网格数量、mesh size、是否可复用网格/模型以及六点与密角度扫描的必要性，而不是直接增加并行度。
